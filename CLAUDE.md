## Repository state

Frappe v15 app hosting a **React SPA dashboard at `/mis`** ("Consumer Business MIS"). Single module: **Company Dashboard**. Data comes from ERPNext (Sales Invoice, Item, Customer Group) — no stubs. Sibling apps `raven` and `excom` are the reference patterns for how the SPA, boot payload, and ERPNext access are wired.

## MIS frontend

- **SPA base route:** `/bizdashboard` — served by `company_dashboard/www/bizdashboard.py` + `bizdashboard.html` (Jinja shell, injects `window.frappe.boot` + `window.csrf_token`). SPA catchall via `website_route_rules` in `hooks.py`.
- **Source:** `frontend/` — Vite 5 + React 18 + TypeScript + Tailwind + `frappe-react-sdk` + recharts + Radix. Green + beige light-mode theme (CSS vars in `src/index.css`, Tailwind tokens mirror them).
- **Design reference:** `sample.html` at the app root is the authoritative visual spec for the MIS pages. Match its palette, type, card/KPI shapes, and grids when building any new page.
- **Build output:** `company_dashboard/public/company_dashboard/` → served at `/assets/company_dashboard/company_dashboard/`. `yarn build` also overwrites `company_dashboard/www/bizdashboard.html` via `copy-html-entry.js` (injects the Jinja `{{ boot }}` + `{{ csrf_token }}` tags before `</head>`).
- **MIS APIs:** `company_dashboard/api/mis.py` — one whitelisted method per page (`get_overview`, `get_sku_assortment`, `get_fiscal_years`, `create_dashboard_user`, …). All return `{period, kpi, ...}`-shaped dicts.
- **WC APIs:** `company_dashboard/api/wc.py` — `get_wc_overview`, `get_bank_detail`, `get_trade_receivable`, `get_trade_payable`, `get_stock_detail`. Uses BNS Pure AR/AP Summary reports with FIFO aging adjustment. Bank accounts filtered by `account_type = "Bank"` (same as BNS bank_gl). Stock from `tabBin`.
- **Access control:** Two independent roles: `MIS Viewer` (gates `/bizdashboard/mis/*`) and `WC Viewer` (gates `/bizdashboard/wc`). The SPA shell allows either role. Both roles auto-created in `seed_defaults`. Boot payload includes `sections: {mis: bool, wc: bool}` so the frontend conditionally shows sidebar nav. Provision users via `create_dashboard_user(email, first_name, mis=True, wc=False)`.
- **Required apps:** `business_needed_solutions` (for BNS AR/AP FIFO aging reports).
- **Phase map:** P1 ✅ Overview. P2 ✅ P&L Waterfall · ✅ SKU Assortment · ✅ Working Capital. P3 ☐ SKU Analysis · ☐ SS/Distributors · ☐ TAM.

### Frontend dev workflow

```bash
# one-time
cd apps/company_dashboard/frontend && yarn install

# dev (from frontend/ — Vite on :8082 proxying /api /app /assets to bench on :8000)
yarn dev

# production build → emits bundle + rewrites www/mis.html
yarn build

# typecheck only
yarn typecheck
```

Run `bench start` (bench root) in parallel with `yarn dev`. Browse http://localhost:8082/mis.

### Frontend rules

- Never hand-edit `company_dashboard/public/company_dashboard/**` or `company_dashboard/www/mis.html` — both are build artefacts, regenerated by `yarn build`.
- All new pages live under `frontend/src/pages/`; add the route in `src/App.tsx` and a nav entry in `src/components/layout/Sidebar.tsx`.
- All backend calls go through `useFrappeGetCall`/`useFrappePostCall` hooks pointing at `company_dashboard.api.mis.<method>` — do not fetch directly, so CSRF + session handling stay correct.
- When you add a new MIS API method, add a matching TS type in `frontend/src/types/mis.ts` and a hook in `frontend/src/hooks/`.

## Architecture notes

- `company_dashboard/hooks.py` — wires `/mis` SPA (`website_route_rules`), boot enrichment (`boot_session = company_dashboard.boot.boot_session`), and the apps-screen tile. Add `doc_events`, `scheduler_events`, `fixtures` here as they land.
- `company_dashboard/api/mis.py` — all MIS queries (whitelisted). Keep page-scoped: one method per route.
- `company_dashboard/www/mis.py` + `mis.html` — SPA shell. `mis.html` is a build artefact.
- `company_dashboard/boot.py` — `boot_session()` decorates `bootinfo` with MIS-specific keys (default company, ERPNext install check, roles).
- `company_dashboard/company_dashboard/doctype/<snake>/` — DocTypes land here; edit JSON via Desk or directly, then `bench migrate`.
- `company_dashboard/patches/` + `patches.txt` — split into `[pre_model_sync]` / `[post_model_sync]`.
- `frontend/` — see "MIS frontend" section above.
